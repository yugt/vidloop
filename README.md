# vidloop

Submission for the Crusoe x Cerebral Valley "Recursive Agents Hackathon" (Oct 17-18, 2026).
Theme: build a team of agents you can walk away from.

**An autonomous video studio that watches its own videos, fixes its mistakes, and writes down what it
learned for the next film.** A team of models storyboards a short film, generates stills and clips,
judges every still, clip and the finished film with several independent judges, edits or regenerates
what fails, and records lessons that the next film's storyboard and prompts read.

**Demo video (57 s, narrated):** [`demo/vidloop_demo.mp4`](demo/vidloop_demo.mp4) - the story first,
then the failed versions it took to get there, then which agent does what.

## Pitch

vidloop started as a self-improving agent that makes short motion-graphics videos by writing code, and
grew into the multi-agent film pipeline above. The code-agent part: a coder
model writes a Python scene, the harness renders it to MP4, and a video-understanding model
(Nemotron Omni) watches the result and critiques it. The coder revises until the video passes.
On top of that, an outer loop has a librarian model read what went wrong across many briefs and
rewrite the agent's own skill library (lessons, helper modules, optionally the system prompt), so
the next generation starts better.

## How it works

```
Inner loop (loop.py, per brief)

  brief -> coder.write -> scene.py -> render (subprocess) -> video.mp4
              ^                                                 |
              |                                          judge.critique
              |                                   (Omni answers checklist)  
              |                                                 |
              +---- coder.revise <---- issues, or render error -+
                    (stop at pass score or max iterations)

Outer loop (evolve.py, per generation)

  for each generation:
      snapshot skills/
      run inner loop on every TRAIN brief and every TEST brief (current library)
      record train and test metrics -> history.jsonl
      librarian.distill(TRAIN trajectories only) -> new lessons.md,
                                                    validated skills/lib/*.py helpers,
                                                    optional new system_prompt.md
      (no distill after the last generation)
```

Roles are spread across three different models; the config notes each model has its own
per-minute rate limit. `llm.chat` retries on HTTP 429/503 with backoff (up to 6 attempts).

### Train and test briefs

`briefs.json` holds 4 `train` briefs and 2 `test` briefs. The librarian only ever receives train
trajectories (`librarian.distill(trajs["train"])` in `evolve.py`). Test briefs are run every
generation but never shown to the librarian, so the test score measures whether the learned skills
generalize to unseen briefs.

### What the librarian can change

- `skills/lessons.md`: the complete lesson list, max 25 rules, one `- ` line each.
- `skills/lib/*.py`: up to 3 new or rewritten helper modules per generation.
- `skills/system_prompt.md`: replaced only if the librarian returns a new one.

The coder sees the system prompt, the contract, the helper signatures (extracted by AST, with the
first docstring line) and the lessons. Each generation's library is copied to
`runs/<timestamp>/gen_N/skills` so it can be diffed.

## The scene contract

The coder must write one self-contained Python file using only Pillow, numpy, math, the standard
library and the helper modules from `skills/lib/`. It must define:

```python
DURATION = 3.0                                   # float seconds, 0 < DURATION <= 10.0
def frame(t: float, W: int, H: int) -> Image.Image:   # RGB, exactly (640, 360)
    ...
```

`frame()` must be a pure function of `t` (no state between calls). The runner (`runner.py`)
imports the file in a subprocess, calls `frame(i / fps, W, H)` for every frame, rejects wrong
sizes or out-of-range durations, and encodes H.264 yuv420p (crf 28, preset veryfast). A crash
prints the traceback and exits non-zero; the traceback tail (4000 chars) is fed back to the coder
as the revision feedback. Helper modules are imported by name via `PYTHONPATH`
(e.g. `from easing import ease_out_back`).

## Judge design decisions

Every one of these came from testing the judge on real renders. The judge went through four designs;
the first three were measured and rejected.

1. **Free-form 0-10 score: rejected.** It gave 9/10 while its own issue list said the required
   scaling and fade animations were missing.
2. **Severity-weighted issue list (median of 3-5 samples): rejected.** Single samples scored the same
   video anywhere from 0 to 10. Even the median could not separate a first draft from a clearly
   better revision (5.25 vs 5.75 over 6 samples each).
3. **Pairwise side-by-side comparison: rejected.** Both candidates in one video, sides swapped between
   samples. The better video won 3 of 6, and the right-hand side was picked 4 of 6 times regardless of
   content: a coin flip with position bias. Swapping in `NVIDIA-Nemotron-3.5-Super-VL` as judge did
   not help (it preferred the worse video).
4. **Fixed per-brief checklist, majority vote** (`judge.py`). The librarian model
   turns each brief once into 12-14 yes/no checks (every brief requirement plus craft checks such
   as easing, margins, no empty opening, final hold), stored in `checklists/` so every iteration,
   generation and run is scored against the same questions. Omni answers all checks with visual
   evidence in each of 5 parallel samples; each check passes on a strict majority; score is
   `10 * passed / total`; failed checks with the judge's evidence are the coder's feedback.
   Repeated scoring of the same video now agrees within about 1.5 points, and on three
   hand-inspected renders it ranked them correctly (it caught an empty first half second and a
   fade-to-black ending). It still misses frame-level glitches such as a single oversized letter
   while text types on.
5. **Checklist grounded in an unprimed description: current design** (`judge.describe`). Negative
   controls showed the checklist judge confirmed elements that were not in the video: judged against
   the podcast brief, a "vidloop" title card with no waveform and no typing scored 7.1, against 7.9 for
   the correct video. Omni now first writes a literal second-by-second description of the video
   without seeing the brief or checks; the checks are then answered with that description in view,
   and any element it does not mention counts as absent. On the same four videos:

   | Video judged against the podcast brief | Checklist only | Grounded |
   | --- | --- | --- |
   | Correct podcast title card | 7.9 | 8.6 |
   | Wrong: "vidloop" title | 7.1 | 2.9 |
   | Wrong: countdown 3-2-1-GO | 4.3 | 1.4 |
   | Wrong: bar chart | 1.4 | 1.4 |

Reliability fixes that apply to every judge call:

- **Measured facts are given, not judged.** The model repeatedly called exact 6.00-second videos
  "about 7 seconds" and filed it as critical. The prompt states measured duration and frame count,
  the checklist excludes them, and when a brief names a length ("6-second") the measured duration
  is added as a fixed pass/fail check (within 0.5 seconds) that the model does not vote on.
- **Reasoning effort "low", and runaway samples are dropped.** At default effort Omni often reasoned
  past 16k tokens without answering (1 in 3 calls); at "low" it uses about 2.5k tokens but still
  runs away on roughly 1 in 6 calls. `llm.chat` raises `TruncatedError` on
  `finish_reason == "length"`; the judge drops that sample and needs at least 3 of 5 to answer.
  Turning reasoning off entirely was measured too: it scored nearly everything 0.
- **Schema-constrained JSON.** One malformed free-form reply crashed an 8-minute evolve run; every
  judge call now sets `response_format` to a JSON schema.

Loop fixes:

- **The inner loop hill-climbs.** Revising the latest code let one bad revision drag every later one
  down (one brief went 7.0, 5.5, 6.0, 2.5). `run_brief` always revises the best version so far.
- **Librarian helpers must work.** Every helper module the librarian writes must include a
  `demo(t, W, H)` that renders successfully in a subprocess, or it is rejected
  (`librarian._validate`).

## Image tool (Qwen-Image)

With `VIDLOOP_IMAGE_TOOL=1` the coder is told it can call
`from vidloop.assets import generate_image` at module level to get a generated background, texture
or illustration (`qwen-image-3.0-pro` on Alibaba Cloud Model Studio), then draw crisp text and
motion on top with Pillow. Images are cached on disk by model, prompt, size and seed
(`assets_cache/`), and a scene may request at most 3 new images per render. The endpoint is set by
`VIDLOOP_IMAGE_BASE_URL` and the key by `ALIBABA_API_KEY`. With the switch off, the coder never hears
about the tool, which is the code-only baseline.

## Video tool (HappyHorse image-to-video)

With `VIDLOOP_VIDEO_TOOL=1` (together with the image tool) the coder can also call
`animate_image(start_image, motion_prompt, duration)` at module level. It submits the still as the
first frame to `happyhorse-1.1-i2v` (480P, 3-10 seconds), polls the async task, caches the MP4 by
image, prompt and duration, and returns the frames resampled to 24 fps and 640x360 so `frame(t)`
can index them and draw text on top. One clip per scene; a new clip takes about 2 minutes, so the
render timeout is 600 seconds. On the Golden Gate fly-under brief the coder wrote both the
first-frame prompt and the camera-move prompt itself; iteration 1 failed 3 of 14 checks (no clear
open-ocean exit, title not confined to the last second, no final hold) and iteration 2 passed all 14.

## Image-to-video director (`vidloop animate`)

`vidloop animate <still.png> ...` turns stills into short clips and checks whether each clip is
meaningful (`animate.py`):

1. Nemotron Omni looks at the still and writes a camera/motion prompt that suits it, plus 3-5
   specific expectations a viewer could verify ("the camera moves closer to the south tower").
2. HappyHorse animates the still with that prompt.
3. Omni watches the clip and votes (same majority vote as the judge) on those expectations plus
   fixed realism checks: starts from the still, no warping or melting structures, objects keep
   their identity, smooth continuous camera, physically plausible motion, clearly visible motion.
4. If it fails, the director rewrites the prompt from the failed checks and tries once more.

Output per still: `runs/animate-<timestamp>/<still>/attempt_N/{clip.mp4,result.json}`, `best.mp4`
and `summary.json`.

## Short films from checked shots (`vidloop film`)

Image-to-video holds up for one simple camera move over a few seconds and breaks down over long,
multi-beat shots (warped steel, a camera that flies under the deck and ends on top of it). So
`vidloop film "<brief>"` cuts a 10-20 second film into shots (`film.py`):

1. **Storyboard:** Nemotron Super writes 3-4 shots of 3-5 seconds, each with a first-frame prompt,
   one camera move, checkable expectations and the story intent, plus shared style notes (light,
   palette, lens) so the shots match.
2. **Shots:** each still comes from Qwen-Image and is animated by HappyHorse; the grounded Omni
   judge checks the clip against the reference still and the shot's expectations, and a failed shot
   is re-planned and regenerated (`animate.make_shot`).
3. **Stitch:** ffmpeg crossfades the shots (0.5 seconds), the title is drawn with Pillow and faded in
   over the final shot, and the film is trimmed to the brief's length.
4. **Two reviewers:** Omni judges the whole film against the brief's checklist, and the contact
   sheets written for every shot (`shot_N/sheet.png`) and the film (`film_sheet.png`) are reviewed
   by a person or a second model. A rejected shot is regenerated with
   `vidloop film --dir <film_dir> --redo N --note "<what was wrong>"`, which re-stitches and
   re-judges the film.

Two more controls, added after review:

- **Must-pass checks.** A shot can list hard facts (`"must"` in the storyboard, e.g. "no flame") that
  fail it whatever its overall score; one failed check out of 12 otherwise still scored 9.2 and passed.
- **Frame chaining for continuous takes.** A shot marked `"continues": true` starts from the previous
  shot's last frame (extracted with ffmpeg) and is joined with a hard cut instead of a crossfade, so a
  move too hard for one clip can be split into simple segments that still play as one camera take.

## The film pipeline as it runs now (`vidloop film ... --codex`)

The short-film pipeline grew into a team of agents with several independent judges. Every stage below
was added because a real failure got through without it (see Results).

```
storyboard (Nemotron Super, reads the notebook)
  per shot, shots in parallel:
    still round: Qwen-Image x3 candidates -> each judged on arrival by Nemotron Omni (describe, then 3 votes)
                 + Codex compares all 3 in parallel -> pick one, or Nemotron Super fixes the prompt (keeping
                 every hard fact) and the next round starts
    clips:       HappyHorse x2 (started speculatively from Omni's top still while Codex is still picking)
                 -> each judged on arrival by Omni (checks) + Nemotron 3.5 Super-VL (critique with prompt
                 edits) + Codex (compares both) -> pick one, or the director re-plans from all three
  stitch (ffmpeg crossfades or hard cuts, Pillow title)
  film judges: Omni (brief checklist + continuity checks) and Codex (all contact sheets + reference images)
  closed loop: Nemotron Super diagnoses the failure -> an EDL edit (trim, hold, mirror, zoom, grade, join)
               or a minimal-change regeneration of one shot -> re-judge
  notebook:    Nemotron Super distills every attempt, verdict and reviewer note into skills/director_lessons.md
```

What each control is for:

- **Shared cast and style** (`cast`, `style`): appended word for word to every still prompt, so the car
  and robot match across shots (a car once changed model between shots).
- **Still gate** (`still_gate.py`): stills are checked before any clip is made. Omni writes a literal
  description first, then votes; Codex compares all candidates. On the human-caught bad still (an
  open-top car and two barriers) the gate failed it on its own: Omni "an open-top convertible with no
  roof visible", Codex "an open-top roadster, not a coupe".
- **First-frame checks** (`still_must`): only facts a first frame can show. End-of-shot checks ("by the
  end the front faces the camera") once made Codex reject correct stills and the reviser turn the car.
- **Must-pass checks** (`must`): hard facts that fail a shot whatever its score (no flame, one barrier,
  no painted arrows, closed roof).
- **Clip panel** (`panel.py`): Super-VL caught the two worst clip failures by itself, with timestamps and
  prompt fixes: "rotates onto its back/roof (pitch/roll) instead of yawing flat" and "a second identical
  car appears ... a duplicate object". Omni passed both.
- **Measured instead of judged:** duration, and whether a clip starts from its still (first-frame pixel
  difference: 0.006 for matches, 0.26-0.35 for mismatches). Asking Omni to compare the still with the
  video made 2 of 3 samples reason past the token cap.
- **EDL edits** (`edl.py`): editorial fixes in ffmpeg instead of regeneration; the loop replaced a
  crossfade that showed two translucent cars with a hard cut.
- **Frame chaining** (`"continues": true`): a shot starts from the previous shot's last frame and is
  joined with a hard cut, for moves too hard for one clip.
- **Reviewer-approved stills** (`still_image`): a person can pin a still; a still rejected for one shot
  became the first frame of the final shot.
- **Reference images** (`references` in the storyboard): e.g. `references/uturn_trajectory.py` draws the
  U-turn choreography (top-down, keyframes, height profile), which Codex compares the shots against.

### Watching the agents

Every model call is traced (`trace.jsonl`) and every exchange is recorded word for word
(`messages.jsonl`, media shown as placeholders) in the film's folder:

```bash
uv run vidloop status runs/film-<ts>              # what each model is doing now, totals, throttling
uv run vidloop log runs/film-<ts>                 # one chronological story: who did what, what failed, what changed
uv run vidloop log runs/film-<ts> --raw --last 8  # the raw prompts and replies
uv run vidloop timeline runs/film-<ts> --last 5   # Gantt chart per model, parallel calls stacked, idle gaps
uv run --env-file .env vidloop probe crusoe --levels 1,4,8,16   # measured provider concurrency
```

Measured on this machine: a Qwen-Image still takes about 55-60 s, a HappyHorse clip about 56 s (55-77 s
over 16 clips), an Omni clip verdict about 66 s; Crusoe served 16 concurrent Nemotron calls at the same
0.7 s latency as one (no throttling), so judges are never the bottleneck and generation is. Alibaba
throttling is retried with back-off and recorded; concurrent Alibaba requests are capped by
`VIDLOOP_ALIBABA_CONCURRENCY` (default 4).

## Quickstart

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
```

Put your keys in a gitignored `.env` file (`.env`, `runs/` and `assets_cache/` are in `.gitignore`):

```
CRUSOE_API_KEY='...'
ALIBABA_API_KEY='...'   # stills, clips, demo narration (Alibaba Cloud Model Studio)
```

The `--codex` reviewer needs the [Codex CLI](https://github.com/openai/codex) installed and logged in.

Commands:

```bash
# Inner loop on one brief (--iters overrides max iterations)
uv run --env-file .env vidloop make "A 5-second countdown from 3 to 1 ..."

# Outer loop: train+test briefs from briefs.json each generation, librarian between generations
uv run --env-file .env vidloop evolve --gens 3

# Render a scene file to MP4, no API calls
uv run vidloop render examples/hello_scene.py out.mp4

# Ask the judge to critique an existing MP4
uv run --env-file .env vidloop judge video.mp4 "<brief>"

# Write a self-contained report.html (score curve, before/after videos, learned skills), no API calls
uv run vidloop report runs/<timestamp>

# Turn stills into checked 3-5 second clips (Omni directs, HappyHorse animates, Omni verifies)
uv run --env-file .env vidloop animate assets_cache/<image>.png --duration 4

# 10-20 second film from checked 3-5 second shots, closed loop and both judges; resume or redo a shot
uv run --env-file .env vidloop film --rounds 2 --codex "A 10-second film of ... ending with the title '...'"
uv run --env-file .env vidloop film --dir runs/film-<timestamp> --rounds 2 --codex
uv run --env-file .env vidloop film --dir runs/film-<timestamp> --redo 2 --note "the tower warps"

# Rebuild the narrated demo from three shot clips
uv run --env-file .env python references/demo_video.py <danger.mp4> <escape.mp4> <home.mp4> demo/vidloop_demo.mp4

# Tests (real subprocess renders, no API calls)
uv run pytest -q src/vidloop
```

`make` writes to `runs/make-<timestamp>/iter_N/` (`scene.py`, `video.mp4`, `critique.json`) plus a
`trajectory.json`, and prints the best video path. `evolve` writes to `runs/<timestamp>/` with one
`gen_N/` per generation and a `history.jsonl` of per-generation metrics (mean first score, mean
best score, mean iterations, pass rate, render failures, for train and test).

## Known limitations

An independent code review (Codex, read-only) found 17 issues; the ones that could crash a run or
corrupt a score were fixed (atomic cache/checklist/trajectory writes, zero-frame and silent-crash
renders, empty checklists, brief-duration scoring, resume against a different brief file, run-folder
collisions, output collisions in `animate`, the clip cap, and the director's reference image).
Deliberately not addressed in the hackathon:

- **Generated code is not sandboxed.** Scenes run in a subprocess with a timeout, but with the
  user's filesystem permissions. Scene code no longer inherits `CRUSOE_API_KEY`; it still gets
  `ALIBABA_API_KEY` because the image and video tools need it. Run it on a machine you don't mind.
- **One evolve run per skills directory.** The librarian rewrites the library in place, so
  concurrent runs must each set their own `VIDLOOP_SKILLS_DIR`. A run that is interrupted during
  the librarian step re-distills on `--resume`.
- **The escape U-turn is still not right.** The Roadster film's middle shot never shows the car visibly
  crossing the median barrier in the air; Codex blocks the film for it while Omni scores it 10/10. The
  demo uses the best take so far. Frame chaining (rise, turn at the apex, descend) is built but not yet
  tried on it.
- **Alibaba access** in this build used a subscription plan key; check your own plan's terms for
  automated use. The `--codex` reviewer bills the Codex user's OpenAI account.
- **The judge misses frame-level glitches** (a single oversized letter while text types on, subtle
  morphing in generated clips) and some checklists miss whole failure classes (a black oval mask
  passed 12 of 12 checks before the generic "fills the whole frame" check was added).

## Results

All numbers below are from runs in `runs/` during the hackathon, scored by the grounded checklist
judge unless stated otherwise. Sample sizes are small; read them as evidence, not proof.

### Self-improvement (`vidloop evolve`, code-only, 2 generations)

**Easy briefs** (`briefs.json`, 4 train + 2 test): first attempts already scored 8.6-10, so there was no
room to measure a gain. Held-out first-attempt score went 8.95 to 9.30, which is one extra check on one
brief, within judge noise. Not counted as an improvement.

**Hard briefs** (`briefs_hard.json`, 4 train + 6 test: dense timing, exact values, several simultaneous
animations):

| Held-out test briefs (never shown to the librarian) | Gen 0, seed library | Gen 1, learned library |
| --- | --- | --- |
| Mean first-attempt score | 7.35 | 6.63 |
| Mean best score within 4 iterations | 9.02 | 9.20 |
| Briefs reaching the 9.0 pass bar | 3 of 6 | 5 of 6 |
| Mean iterations | 3.0 | 2.67 |

The learned library did not make first attempts better (one gen-1 first attempt crashed), but the loop
using it finished more unseen briefs, in fewer iterations. With 6 briefs and one generation this is a
modest, not a significant, result. What the librarian wrote is in `runs/skills_hard/`: 10 lessons drawn
from the judge's failures (visible change every second, hide letter-by-letter text until it types,
ease every animated property, stagger sequences, check tickers loop seamlessly) and an `alpha_shapes`
helper that passed its render gate.

### Judge validity

- Free-form score: gave 9/10 to a video missing two required animations.
- Checklist without grounding: a wrong video ("vidloop" title) scored 7.1 against the podcast brief whose
  correct video scored 7.9.
- Grounded checklist (current): correct 8.6-9.3, wrong videos 1.4-2.9 on the same brief.
- Known misses, found by a human/second-model review of contact sheets: a ghosting, wrongly shaped tower
  (judge 10/10), a car that changed model between shots (judge 10/10, it sees one shot at a time), and a
  black oval mask (12/12 before the "fills the frame" check existed).

### Films (`vidloop film`, Qwen-Image stills + HappyHorse clips, 10 seconds)

- **Golden Gate, 10-second cut:** 3 shots kept out of 4 after review (the tower shot was rejected for
  ghosting); film judge 8.7.
- **Roadster story, barrier version** (`demo/roadster_film.mp4`): the full multi-agent pipeline. The
  danger shot and the final shot pass both judges; the escape shot takes off from the right heading and
  turns flat, but does not visibly cross the barrier, so the film fails Codex's review (6 blocking issues
  at the last check) while Omni scores it 10/10. The multi-judge design is the reason this is visible.
- **Roadster story, earlier versions** (a robot drives north, a landslide blocks the road, the car takes off while moving,
  spins around in mid-air and lands southbound, "Safe Return"): six versions. Each fix came from review:
  the storyboard model diluted the story into scenery (v1, rewritten one beat per shot); the car changed
  model between shots (shared `cast` text); flames and a red car contradicted the real demo (news
  coverage: compressed-air cold-gas thrusters, stark-white angular car); the take-off stopped and the
  turn was split across cuts (one continuous fixed-camera escape shot); and the jets glowed like flames
  (a must-pass "no glow" check). The real demo video was used only as a reference for how the thrusters
  look and is not in the repo or the films.
